# lisa-pack-markdown

Lisa markdown pack — memory-grounded markdown document forging with `markdown-it-py`.

The pack turns a user instruction into a markdown document that is (a) grounded in recalled long-term memory, (b) structurally validated, and (c) persisted to the `lisa-storage` MCP server. It never touches the local filesystem directly — all reads (memory) and writes (storage) go through `ctx.host.execute_tool`.

## What it provides

| Layer | Path | Role |
| --- | --- | --- |
| Operations | `operations/forge_document/`, `operations/consolidate/` | The two workhorses (single-doc and multi-source). |
| Tool | `tools/markdown_generate/` | An in-process, read-only structural validator backed by `markdown-it-py`. |

### Operations

- **`markdown_forge_document`** — combine user input with recalled memory context (and optionally an existing document), synthesize or revise a markdown document via an LLM, validate its structure, and persist it to `lisa-storage`.
- **`markdown_consolidate_sources`** — consolidate multiple source documents into one coherent markdown document, preserving per-source detail (anti-abridgment). Reads every source via `lisa-storage`, injects them with per-source NL priority notes, applies map-reduce when the aggregate is large, enforces a density floor against lossy summarization, and captures OKF provenance.

### Truncation handling

When the LLM stops mid-document, the operation issues continuation passes until the document looks complete or the continuation budget is exhausted. The decision is driven by the **provider-owned `truncated` signal** on the completion result (`ctx.host.complete(...).truncated`), not by guessing from `finish_reason` strings:

- `truncated=True` → the model hit its token budget; continue up to `forge_max_continue_attempts` passes.
- `truncated=False` → clean stop; no continuation (unless the document ends on a dangling heading with no body — a structural override).
- `truncated=None` → adapter cannot tell (e.g. a local backend that omits the signal); one safety-net continuation pass, then stop.

The persisted document carries a `<!-- generated by lisa · ... -->` annotation noting the model and whether it was truncated.

### Outline contract (self-abridgment defense)

A clean stop is not the same as a complete document: a model may declare a
section plan and then quietly omit the last sections while reporting
`truncated=False` (the 2026-10-16 `docs/unveil-strategy-2026-10-16.md`
incident — sections 4–5 never written, no continuation fired). The forge
user prompt asks the model to declare its section plan as a first-line
`<!-- forge-plan: ## A / ## B -->` comment inside the fenced block. The
operation strips that marker (it never reaches the persisted document),
diffs the plan against the document's actual `##` headings with fuzzy
matching, and when sections are missing runs up to
`forge_outline_contract_attempts` expansion passes that write only the
missing sections under their declared headings. Gate behavior:

- No plan marker → gate skipped entirely; legacy path, zero extra LLM calls.
- Plan declared and satisfied → gate passes, zero extra LLM calls.
- Sections missing → expand passes; a document still missing sections after
  the budget persists with `status="degraded"`, a summary warning, and a
  `missing sections: ...` line in the trailing annotation (never a hard
  reject).

Telemetry lands in `OperationResult.extra["outline_contract"]`
(`planned`, `missing_before`, `missing_after`, `attempts`, `stop_reason`)
and the structured `forge.outline_contract:` log line.

### The `markdown_generate` tool

A pure read-effect tool that parses a markdown string with `markdown-it-py` and returns a normalized structural outline. It never touches the filesystem. It accepts the markdown text on `parameters["markdown"]` (or `ctx.query` as a fallback) and returns the outline on `output_json` plus a one-line summary on `output_text`.

**`output_json` shape:**

```json
{
  "heading_count": 3,
  "headings": [{"level": 1, "text": "Title"}, {"level": 2, "text": "Section"}],
  "lists": {"ordered": 1, "unordered": 2, "max_depth": 2},
  "code": {"fenced_blocks": 1, "inline_spans": 4},
  "has_content": true
}
```

## Reusing `markdown_generate` from other packs (opt-in)

`markdown_generate` is a stateless, read-only primitive — other packs can deliberately adopt it. The tool yml declares **no** `mode_allowlist`, so there is no tool-level mode restriction; reuse is opt-in purely at the consumer side:

1. A consuming mode adds `markdown_generate` to its `allowed_tool_ids` (in its `_mode.md`), or
2. a consuming operation lists it in its own `tool_ids` (as `forge_document` and `consolidate` do).

The pack `lisa-pack-markdown` must be installed in the host environment.

### Promotion rule

`markdown_generate` remains in the markdown pack until **three or more** consumers outside this pack (modes or operations) adopt it. Promotion to a shared/core tool location is a separate, deliberate decision deferred until the consumer count proves the need.

## Configuration

Budgets and behavior are resolved from `ctx.pack_config` (the session manifest's `resources.packs.configuration.markdown.<key>` block) with module-constant fallbacks. Notable keys:

| Key | Default | Purpose |
| --- | --- | --- |
| `forge_max_completion_tokens` | 50000 | First-pass LLM token budget. |
| `forge_max_continue_attempts` | 4 | Max continuation passes on truncation. |
| `forge_max_document_chars` | 20000 | Hard char cap on the persisted doc. |
| `forge_lint_rules` | (curated subset) | CSV of `pymarkdownlnt` rule IDs; overrides the structural default. |
| `forge_lint_repair` | true | Gate the single lint repair pass; false persists an advisory comment. |
| `forge_tokens_per_word` | 1.3 | Words→tokens translation factor for `target_length`-driven budgeting. |
| `forge_outline_contract` | true | Expand passes for planned-but-missing sections when the model declares a `forge-plan`. |
| `forge_outline_contract_attempts` | 2 | Max expansion passes per forge for the outline contract. |
